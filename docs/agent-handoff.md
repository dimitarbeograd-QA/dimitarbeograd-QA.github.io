# Предаване на работа между агенти

Когато един агент (Jules, Gemini CLI, Aider, Claude и др.) спре — изчерпан лимит, грешка или край на сесията — следващият трябва да продължи от същото място, без да започва отначало.

## Правила

1. **Работата живее в Git, не в модела.** Всеки агент работи в отделен клон `agent/<задача>` (напр. `agent/DTO-17-faq`) и никога директно в `main`.
2. **Малки и чести commit-и.** След всяка завършена стъпка: `git commit`. Некомитнатата работа се губи при внезапен край.
3. **Бележка за предаване.** Преди да спре (или при всеки значим етап) агентът добавя бележката по-долу като коментар в Jira задачата и/или във файл `HANDOFF.md` в клона. `HANDOFF.md` се изтрива при сливане в `main`.
4. **Следващият агент** започва с: четене на бележката, `git log` и `git diff main`, пускане на тестовете, и чак тогава продължава.
5. **Не се въвеждат пароли, ключове и лични данни** на клиенти в бележките.

## Шаблон на бележката

```
ПРЕДАВАНЕ — <Jira ключ> — <дата и час>
Агент: <кой е работил>  →  Следващ: <кой продължава или "който е свободен">
Клон / последен commit: <agent/...> / <хеш>

Цел:
<едно изречение>

Готово:
- ...

Остава:
- ...

Не е тествано / известни проблеми:
- ...

Решения, които не бива да се променят:
- ...

Как се пуска / тества:
<команди>
```

## Ротация

В Jira задачата се записва кой агент я работи. При изчерпан лимит се взима следващият свободен агент по реда: Jules → Gemini CLI → Aider (локален модел) → Claude (преглед и довършване).
Лимитите на тези инструменти се виждат само в собствените им табла, затова превключването е ръчно.
